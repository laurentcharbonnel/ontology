# Architecture questions and next steps

## Decisions to investigate
1. **Scope:** enterprise-wide upper ontology versus domain-specific ontologies.
2. **Governance:** central stewardship versus federated domain ownership.
3. **Representation:** lightweight SKOS/RDF versus OWL and formal reasoning.
4. **Modeling boundaries:** ontology, conceptual data model, logical model and physical model responsibilities.
5. **Identifiers:** canonical concept IDs versus entity instance IDs and domain-local keys.
6. **Integration:** metadata catalog, data contracts, entity resolution and semantic consumption.
7. **Lifecycle:** versioning, backward compatibility, change impact and review workflow.
8. **Tooling:** authoring, validation, visualization and automated mapping support.

## Proposed next workshop
Choose one bounded business example (e.g. Company, Fiscal Calendar, Reporting Period). Capture five competency questions, define the business concepts and rules, then derive a conceptual and logical model. Compare what information is preserved, added or transformed at each step.

## Expected outputs
- A validated small ontology
- One conceptual model
- One logical model
- A mapping/traceability matrix
- An ADR recording modeling boundaries and ownership

These are initial hypotheses and discussion prompts, not finalized design decisions.
